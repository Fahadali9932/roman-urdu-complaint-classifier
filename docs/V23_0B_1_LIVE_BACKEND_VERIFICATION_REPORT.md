### Remote Tracking Divergence:
Remote staging contains historical migration rows with autogenerated timestamps (`20261120121507`, etc.) created during earlier ad-hoc schema pushes. Because local filenames follow the normalized date convention (`20261121195517_...`), running `npx supabase db push --remote` halts with `DbPushMissingLocalError: Remote migration versions not found in local migrations directory`.

**Truthful Resolution:**
To apply pending migrations `20261207000000` and `20261208000000` safely without dropping tables or breaking existing data:
1. Local schema is 100% additive and idempotent (`IF NOT EXISTS`, `ON CONFLICT DO UPDATE`, `DROP POLICY IF EXISTS`).
2. Rollout to remote staging should be performed by applying the SQL statements via the Supabase Dashboard SQL Editor or direct psql session, followed by `npx supabase migration repair --status applied <version>` to synchronize tracking tables.

## 5. DATABASE SECURITY HARDENING

Three critical security flaws in the database layer were audited and corrected in `supabase/migrations/20261208000000_v23_0b_database_reconciliation.sql`:

### 1. View Security Invoker Enforced
```sql
CREATE OR REPLACE VIEW public.v23_operational_cases_view
WITH (security_invoker = true) AS
SELECT ...
FROM public.department_work_orders w
JOIN public.complaints c ON c.id = w.anchor_complaint_id;
```
Without `security_invoker = true`, PostgreSQL views default to running with the privileges of the view owner (often `postgres`), completely bypassing Row-Level Security on `department_work_orders` and `complaints`. With `WITH (security_invoker = true)`, PostgreSQL enforces the executing user's RLS policies.

### 2. Cross-Department Profile Photograph Leak Elimination
Previously, the select policy for `staff-profile-photos-private` checked only if the caller was an active Department Head, allowing an HOD in K-Electric to view profile photos of officers in KMC or SSGC.
The policy was corrected to strictly enforce departmental matching:
```sql
CREATE POLICY v23_staff_profile_photos_select ON storage.objects
FOR SELECT TO authenticated
USING (
  bucket_id = 'staff-profile-photos-private'
  AND (
    (storage.foldername(name))[1] = auth.uid()::text
    OR EXISTS (
      SELECT 1
      FROM public.department_memberships head_mem
      JOIN public.department_memberships officer_mem
        ON head_mem.department_id = officer_mem.department_id
      WHERE head_mem.user_id = auth.uid()
        AND head_mem.staff_role = 'head'
        AND head_mem.status = 'active'
        AND officer_mem.user_id::text = (storage.foldername(name))[1]
        AND officer_mem.status = 'active'
    )
    OR public.is_main_admin(auth.uid())
  )
);
```

### 3. Safe Function Execution & Restricted Grants
- Explicitly set `search_path = ''` on `v23_sync_multi_dept_complaint_status` and triggers to prevent schema poisoning attacks.
- Explicitly revoked public access:
```sql
REVOKE EXECUTE ON FUNCTION public.v23_sync_multi_dept_complaint_status(uuid) FROM PUBLIC, anon, authenticated;
GRANT EXECUTE ON FUNCTION public.v23_sync_multi_dept_complaint_status(uuid) TO service_role;
```

## 7. OFFICER CONTACT EMAIL & CRYPTOGRAPHIC OTP ARCHITECTURE

### 1. Delivery & Contact Email
- Replaced synthetic `staff+...` non-deliverable email pattern with genuine `contactEmail` input in HOD officer provisioning (`create_officer`).
- Stored in `officer_profile_details.contact_email` and used for dispatching verification notices.

### 2. Table Schema (`officer_onboarding_otps`)
```sql
CREATE TABLE IF NOT EXISTS public.officer_onboarding_otps (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  user_id uuid NOT NULL REFERENCES auth.users(id) ON DELETE CASCADE,
  contact_email text NOT NULL,
  otp_hash text NOT NULL,
  salt text NOT NULL,
  attempts_count integer NOT NULL DEFAULT 0,
  max_attempts integer NOT NULL DEFAULT 5,
  expires_at timestamptz NOT NULL,
  resend_cooldown_until timestamptz NOT NULL,
  verified_at timestamptz,
  created_at timestamptz NOT NULL DEFAULT now()
);
```

### 3. Edge Function Implementation (`manage-department-officers`)
- **`send_onboarding_otp`:**
  - Enforces 60-second resend cooldown (`resend_cooldown_until`).
  - Generates 6-digit cryptographically random code via `crypto.getRandomValues`.
  - Generates 16-byte random salt; hashes code via `SHA-256(salt + ":" + code)`.
  - Sets 5-minute expiration timestamp.
  - Plaintext code is **never logged** to console or audit tables.
  - Sends email via external provider (e.g., Resend / Brevo) if configured.
- **`verify_onboarding_otp`:**
  - Validates 6-digit format.
  - Enforces expiration check and max 5 attempts limit.
  - Performs timing-safe comparison against salted SHA-256 hash.
  - Sets `verified_at` and unlocks onboarding status.

### 4. Zero-Cost Free SMTP Tier Truth
- **Supabase Auth Built-in SMTP:** Strictly limited to 2-4 emails per hour (suitable only for developer testing; rejects high-volume onboarding).
- **Brevo Free Tier:** 300 emails/day with zero credit card required.
- **Resend Free Tier:** 3,000 emails/month (100 emails/day) with zero credit card required.
- **Fallback Guarantee:** Cryptographic Temporary Access Key + Forced First-Login Password Reset remains 100% functional even when zero SMTP services are configured.
